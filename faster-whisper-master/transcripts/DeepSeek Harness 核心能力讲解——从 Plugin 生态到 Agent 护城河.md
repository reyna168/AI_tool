# DeepSeek Harness 核心能力讲解——从 Plugin 生态到 Agent 护城河

## 一、什麼是 DeepSeek Harness

DeepSeek Harness（以下簡稱 Harness）是一套 **AI Agent 執行環境**，野心非常大——它想做成 AI 時代的 Android，一個開放式平台，所有人都可以修改和擴展。

### 核心理念：萬物皆可插件

與 Claude、Cursor 等 Agent 平台不同，Harness 的核心思想是：

> **一切皆是插件** —— 模型可以換、工具可以換、提示詞可以換、文件系統、沙箱、子 Agent 等等，全部都可以替換。

| 平台 | 架構比喻 | 可替換程度 |
|------|---------|-----------|
| Claude / Cursor | iOS（完整產品封裝） | 資源層插件（MCP、Skill） |
| LangChain / CrewAI | 更靈活，暴露 API 但流程固定 | 流程中部分環節可替換 |
| **DeepSeek Harness** | **Android（完全開放）** | **所有組件皆可替換** |

---

## 二、安裝與啟動

1. 開啟終端機，執行安裝指令
2. 首次安裝需下載較多依賴，可能等待 10+ 分鐘（過程中無提示，並非當機）
3. 啟動後提供一個網址，在瀏覽器中訪問即可使用

### 初次使用設定

- **Workspace**：設定文件存放路徑
- **Model API Key**：從 DeepSeek 官網取得 API Key 並填入

## 三、四種運行模式

Harness 提供四種模式，差異在於 **可用工具的範圍**：

| 模式 | 用途 | 可用工具 |
|------|------|---------|
| **標準模式** | 日常使用，一般對話 | 大部分工具 |
| **PZ 模式** | 批次處理大量文件 | 封裝成腳本，避免反覆調用模型 |
| **極限模式** | 評測基礎模型能力 | 僅保留文件編輯和終端命令 |
| **創作模式** | 開發自訂插件 | 包含插件改裝能力 |

### PZ 模式（批次處理）

傳統 Agent 讀取 100 個文件的流程：

```
讀取文件 1 → 放入模型 → 讀取文件 2 → 放入模型 → ... → 循環 100 次
```

PZ 模式的做法：

```
讀取全部 100 個文件 → 封裝成腳本一次執行 → 結果全部塞入模型
```

**優勢**：避免反覆調用模型，大幅提升吞吐效率。特別適合 AI Coding 場景。

### 極限模式（模型評測）

只保留最基礎的工具（腳本 + 文件編輯），移除所有增強能力。用途：

- 公平比較不同模型的基礎能力
- 避免「放一堆調料比誰做的菜好吃」的不公平評測

> 日常開發不建議使用此模式。

### 創作模式（插件開發）

用於開發自訂插件。操作方式：

1. 選擇「創作模式」
2. 開放完整權限
3. 描述你想要的插件功能
4. Harness 自動生成插件代碼

## 四、提示詞系統設計

### 預設提示詞結構

預設提示詞約 **13K~16K tokens**，包含：

- 環境說明
- 文件操作規範
- 後台任務處理
- 數據約數
- 聯網能力
- 輸出格式要求

定義了 AI 在整個執行環境中的行為規範。

### 提示詞快取優化策略

傳統方式：修改中間任意一段 → 後面所有提示詞快取失效

Harness 的策略：**全部採用「追加」而非「修改」**

```
原有提示詞（快取有效）  →  追加新內容（不影響前段快取）
```

**優勢**：
- 降低延遲成本
- 提升響應速度
- 確保穩定部分的快取仍然有效

## 五、插件生態系統

### 插件市場

- 官方插件：從 Harness 官網取得
- 社區插件：支援第三方開發者上傳
- 安裝方式：在對話框中直接輸入指令即可自動安裝

### 插件架構特點

1. **工具註冊**：插件會先註冊為工具，供 Agent 調用
2. **副作用收集**：安裝插件時收集所有副作用，卸載時自動回滾
3. **依賴管理**：插件 A 依賴服務 B，若 B 消失則自動處理
4. **可逆性**：支援完整卸載，不留殘留

### 開發自訂插件的流程

以「飛書通知插件」為例：

```
1. 選擇創作模式 → 開放權限
2. 描述需求：「開發一個飛書通知插件，任務完成後發送消息」
3. Harness 自動生成插件
4. 插件包含：
   - 工具註冊（定義工具名稱和參數）
   - 執行邏輯（調用飛書 API 發送消息）
5. 測試 → 調整 → 完成
```

### 多模態模型插件

透過插件擴展視覺能力：

```
創作模式 → 輸入「幫我開發一個視覺圖片解析插件，調用千問視覺模型」
→ 插件自動生成 → 即可支援圖片理解
```

## 六、技術架構

### 核心循環

```
Agent Loop（智能體循環）
    ├── 文件系統
    ├── 終端命令
    ├── 沙箱
    ├── Shell
    ├── 子智能體
    └── ...所有組件皆可替換
```

與 Claude Code 等工具乍看相似，但關鍵差異在於：**所有模組都可以被替換**。就像樂高積木，整個系統是一塊可自由拼裝的組件。

### 為什麼選擇全插件化？

技術發展速度太快（MCP、Skill 等新技術不斷出現），與其自己開發框架後不斷推翻重來，不如：

> **既然技術路線難以固定，那就全部做成可替換。**

## 七、總結

| 重點 | 說明 |
|------|------|
| 定位 | AI 時代的 Android — 開放式 Agent 平台 |
| 核心理念 | 萬物皆可插件，所有組件可替換 |
| 四種模式 | 標準、PZ（批次）、極限（評測）、創作（插件開發） |
| 提示詞策略 | 追加而非修改，最大化快取效率 |
| 插件生態 | 支援社區開發，可逆安裝，依賴自動管理 |
| 適用場景 | 公司開發智能體、個人 AI 工具擴展 |
| 發展建議 | 不要對抗生態，而是豐富生態 — 大量開發插件 |

> **打不過就加入** —— 與其自己做框架，不如在 Harness 生態中開發插件，這才是有價值的方向。
