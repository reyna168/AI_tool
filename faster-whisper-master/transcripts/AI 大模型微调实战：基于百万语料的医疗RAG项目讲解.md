# AI 大模型微調實戰：基於百萬語料的醫療 RAG 項目講解

## 一、項目概述

這是一個基於 **RAG（Retrieval-Augmented Generation，檢索增強生成）** 技術的醫療 AI 助手項目。

| 項目數據 | 數值 |
|---------|------|
| 訓練語料 | **170 萬** 條醫療問診數據 |
| 覆蓋病種 | **790** 種常見疾病 |
| 基礎模型 | ChatGLM-6B |
| 技術棧 | BERT 向量化 + 向量檢索 + 大模型生成 |

### 實際效果展示

使用者輸入症狀後，系統會：

1. 從 170 萬條數據中檢索相關病例
2. 提取對應的病情描述和治療方案
3. 由大模型生成綜合回答

**範例**：輸入「拉肚子拉了三次怎麼辦」→ 系統回答包含大便常規檢查、少食多餐、多喝水、抗酸藥物等建議。

## 二、為什麼需要 RAG

### 2.1 傳統大模型的痛點

| 問題 | 說明 |
|------|------|
| **即時資訊無法利用** | 訓練成本高、週期長，無法快速吸收最新資訊；可能出現知識矛盾（如總統是誰） |
| **垂直領域知識缺失** | 大模型擅長通用常識，但醫療、金融、公司內部知識等垂直領域無法覆蓋 |
| **訓練成本高昂** | 大廠訓練一次成本也很高，更何況中小企業 |

### 2.2 大模型 + 知識庫的互補

將人的能力分為兩種：

```
大模型 = 聰明（推理能力強）→ 但缺乏特定知識
知識庫 = 記憶力強（知道很多東西）→ 但不會推理
```

> **RAG = 聰明 + 記憶力 = 人類智能**

RAG 的核心思想：**將大模型的推理能力與知識庫的記憶能力結合**。

---

## 三、RAG 整體流程

### 3.1 經典流程

```
用戶提問
    │
    ▼
問題向量化（BERT）
    │
    ▼
向量相似度匹配（知識庫向量化後的結果）
    │
    ▼
召回相關知識（Top-K）
    │
    ▼
提示詞工程（問題 + 召回知識 → 拼接）
    │
    ▼
大模型生成回答
    │
    ▼
輸出結果
```

### 3.2 兩大核心能力

| 能力 | 實現方式 |
|------|---------|
| **記憶力** | 向量化 + 向量檢索（知識庫） |
| **智力** | 大模型推理（生成回答） |

## 四、知識庫構建

### 4.1 數據處理流程

```
原始數據（對話、文檔、PDF、Excel 等）
    │
    ▼
格式轉換（統一轉為文字）
    │
    ▼
數據清洗（去除髒數據、忽略圖片）
    │
    ▼
文本切分（Chunking）
    │
    ▼
向量化（BERT 等 Embedding 模型）
    │
    ▼
存入向量數據庫（ID + 向量）
```

### 4.2 文本切分策略

**理想狀態**：一段文字對應一個知識點（但實際操作中很難實現）

**常見切分方式**：

| 方式 | 說明 |
|------|------|
| **按段落分** | 一個自然段落 = 一個知識點 |
| **按句子分** | 例如 3 個句子為一段 |
| **按 Token 數分** | 例如 100 個 Token 為一段 |

**關鍵技巧：前後重疊（Overlap）**

```
段落 1：[句子 A][句子 B][句子 C]
段落 2：              [句子 C][句子 D][句子 E]  ← 與段落 1 有交集
段落 3：                          [句子 E][句子 F][句子 G]
```

- 目的：減緩一個知識點被切斷的問題
- 注意：是「減緩」不是「解決」，實際工程中無法保證 100%

### 4.3 領域知識處理

對於專業術語（如「交叉韌帶」等），向量模型可能無法理解，需要：

- 額外補充專業詞典
- 輔助外部資料
- 用 RAG 技術拓展

## 五、檢索技術

### 5.1 向量檢索（基礎）

```
用戶問題 → 向量化 → 找最近的 Top-K 個向量 → 返回對應知識
```

### 5.2 文本過濾（提升精度）

向量檢索可能出現「兩句話沒有一個字相同但向量接近」的情況，因此可以加上文本限制：

- 問題包含「肚子疼」→ 知識中必須包含「胃疼」「腸子疼」「肚子不舒服」等類似詞
- 建立詞表規則，確保文字上有共同描述

### 5.3 樹狀索引（高級檢索）

將知識點組織成樹狀結構：

```
腸胃不舒服
├── 腹瀉
├── 便秘
└── 消化不良
胃不舒服
├── 胃酸過多
├── 胃疼
└── 胃穿孔
```

用戶問「肚子不舒服」→ 召回「腹瀉」和「便秘」相關知識

### 5.4 關鍵詞檢索

每個知識點對應幾個關鍵詞，用戶問題命中關鍵詞時召回相應節點。

### 5.5 知識圖譜檢索

召回某個節點後，同時召回相鄰節點（拓展知識）。

> **注意**：知識圖譜構建成本非常高，除非要求嚴格，否則樹狀索引或關鍵詞索引通常已夠用。做工程一定要考慮**成本問題**（構建成本 + 維護成本）。

## 六、排序模型（Re-ranking）

### 6.1 兩階段架構

```
階段 1：召回模型（Bi-Encoder）
    兩句話分別過 BERT → 得到兩個向量 → 計算餘弦相似度
    ↓
階段 2：排序模型（Cross-Encoder）
    兩句話拼接過 BERT → 二分類 Softmax → 輸出 0~1 相關性分數
```

| 項目 | 召回模型 | 排序模型 |
|------|---------|---------|
| 架構 | Bi-Encoder（共享參數） | Cross-Encoder |
| 輸入 | 兩句話分別輸入 | 兩句話拼接輸入 |
| 輸出 | 向量 → 餘弦相似度 | 二分類分數（0~1） |
| 速度 | 快（可離線預計算） | 慢（需即時計算） |
| 用途 | 大規模召回 | 精排 Top-K |

### 6.2 訓練數據

- 約 **180 萬** 條標註數據
- 標籤：1 = 兩句話匹配，0 = 不匹配
- 範例：「腰疼大腿側面腳腕疼 強制性脊柱炎」→ 標籤 1（匹配）

### 6.3 訓練方式

兩個模型**共享參數**，分別用相同的數據訓練：

```
訓練召回模型：用 180 萬條數據
訓練排序模型：用相同的 180 萬條數據
```

## 七、RAG Fusion（進階技術）

### 7.1 核心思想

對用戶原始問題進行**擴展**，生成多個相似問題，然後融合召回結果。

```
用戶問題：「拉肚子怎麼辦」
    │
    ▼
大模型生成類似問題：
  ├── 「腹瀉怎麼辦」
  ├── 「吃壞肚子怎麼辦」
  ├── 「拉稀怎麼辦」
  └── 「肚子不舒服怎麼辦」
    │
    ▼
5 個問題一起召回 → 排序 → 取 Top-3
```

### 7.2 優勢

- 防止用戶輸入過於口語化導致召回失敗
- 擴展檢索覆蓋面
- 結合大模型的理解能力提升召回質量

---

## 八、提示詞工程（Prompt Engineering）

### 8.1 提示詞結構

```
系統指令：
你是醫療助手，根據以下病例為用戶提供治療建議。

參考案例 1：
- 病情描述：{召回知識 1 的病情描述}
- 治療方案：{召回知識 1 的治療方案}

參考案例 2：
- 病情描述：{召回知識 2 的病情描述}
- 治療方案：{召回知識 2 的治療方案}

參考案例 3：
...

用戶問題：{用戶的病情描述}

請根據上述治療方案，結合用戶的病情描述，給出建議。
```

### 8.2 關鍵原則

- 提供 3 個最相關的參考案例（不需要太多）
- 結合大模型的歸納能力，融合多個案例的治療方案
- 大模型在此起「綜合歸納」作用，而非直接複製

## 九、模型微調（SFT）

### 9.1 三個技術的關係

```
RAG 技術 ────┐
              ├── 可以綜合使用，不互斥
大模型原生能力 ─┤
              │
SFT 微調 ────┘
```

> **RAG、大模型原生能力、SFT 微調三者不矛盾，可以同時使用。**

### 9.2 為什麼要微調

- 開源 BERT 模型是通用訓練的，對醫療垂直場景匹配效果不佳
- 需要用醫療數據微調召回模型和排序模型
- 微調後的模型能更準確地匹配醫療術語

---

## 十、評估方法

### 10.1 檢索質量評估

| 指標 | 說明 |
|------|------|
| **MRR（平均倒數排名）** | 相似平均分越高越好 |
| **UC（相關性分數）** | 標註數據後計算，不相似的平均分越低越好 |

### 10.2 最終效果評估

```
找 1000 個問題 → 大模型回答 → 人類打分
    │
    ├── 人類評分平均 95 分
    └── 醫生評分平均 94 分
    → 認為模型效果已達標
```

> **不要追求完美主義**——技術都是在誤差範圍內做相對提升，比人好或比自己之前好就夠了。

---

## 十一、動態數據處理

如果數據是動態更新的：

- 接入 Kafka 等消息隊列
- 新數據實時寫入向量數據庫
- 知識庫持續補充更新

---

## 十二、技術總結

| 技術要點 | 說明 |
|---------|------|
| **知識庫構建** | 數據清洗 → 文本切分（帶重疊） → 向量化 → 存入數據庫 |
| **檢索策略** | 向量檢索 + 文本過濾 + 樹狀索引 + 關鍵詞索引 |
| **RAG Fusion** | 大模型改寫問題 → 多路召回 → 融合排序 |
| **排序模型** | Bi-Encoder 召回 + Cross-Encoder 精排 |
| **模型微調** | 用醫療數據微調 BERT 召回/排序模型 |
| **提示詞工程** | 拼接用戶問題 + Top-K 召回案例 → 大模型生成 |
| **評估** | 人類評分 + 標註數據計算指標 |

### 核心理念

> **不要以完美主義要求技術** —— 實際做一遍，很多問題自然就不是問題了。RAG、微調、大模型原生能力可以綜合使用，不互斥。
